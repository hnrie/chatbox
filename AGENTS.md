# AGENTS.md

## Cursor Cloud specific instructions

This repo is **Chatbox Community Edition** — a local-first **Electron + React/TypeScript** desktop AI chat client, managed with **pnpm** (workspace: `.` and `release/app`). There is **no backend server or database to run**: the app stores data on-device and talks directly to third-party LLM provider APIs. Standard commands live in `package.json` `scripts` and the README "Development" section.

### Services / how to run
- **Dev app (the whole product):** `pnpm dev` (alias of `electron-vite dev`). Serves the renderer on `http://localhost:1212` and launches the Electron window. Other variants: `pnpm dev:web` (browser-only), `pnpm dev:local` (USE_LOCAL_API). It is a single product; there are no other services to start.
- **Lint:** `pnpm lint` (Biome). **Typecheck:** `pnpm check` (`tsc --noEmit`). **Test:** `pnpm test` (Vitest). **Build:** `pnpm build` (electron-vite).
- The default `pnpm test` run excludes `test/integration/model-provider` (needs real provider API keys, e.g. `TEST_OPENAI_API_KEY`).

### Non-obvious caveats
- **Generated route tree is required before `pnpm test` / `pnpm check`.** `src/renderer/routeTree.gen.ts` is git-ignored and generated by the TanStack Router plugin during `pnpm dev` or `pnpm build`. On a fresh checkout, one test suite (`context-tokens.integration.test.ts`) and the typecheck fail with `Failed to resolve import "./routeTree.gen"`. Run `pnpm build` (or start `pnpm dev`) once to generate it, then tests/typecheck pass.
- **`pnpm lint` reports pre-existing errors/warnings** (~11 errors, ~900+ warnings) in the current codebase. This is the repo's baseline, not caused by setup; lint itself runs fine.
- **Running the GUI is headless.** A display is available at `DISPLAY=:1` (Xvfb). The Electron app launches fine; the `Failed to connect to the bus` (DBus) and `Gtk: gtk_widget_add_accelerator` errors in the log are benign in this container and do not indicate failure.
- **`zipfile` native module fails to build during install** because only `python3` (not `python`) is on PATH. This is a transitive dependency that is not used by the app source, and `pnpm install` still completes successfully — it does not block dev/build/test.
- **Real AI responses need a provider configured in-app.** Without an API key the UI runs but cannot get LLM responses. To test the chat flow end-to-end without a paid key, configure the OpenAI provider in Settings → Model Provider with a custom API Host pointing at a local OpenAI-compatible mock (or a local Ollama at `http://localhost:11434`).
